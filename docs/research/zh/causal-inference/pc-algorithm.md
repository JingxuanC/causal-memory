# Spirtes, Glymour & Scheines (2000) — 因果、预测与搜索

## 完整引用

Spirtes, P., Glymour, C., & Scheines, R. (2000). *Causation, Prediction, and Search* (2nd ed.). MIT Press. ISBN: 978-0262194402

## 摘要

本书介绍了**PC 算法**和相关的基于约束的方法，用于**自动化因果发现**——仅根据观测数据推断因果 DAG。关键洞察是数据中的条件独立性关系对可能的因果结构施加了约束。通过系统地测试这些约束，算法可以将与数据一致的因果图集缩小。

PC 算法（以其作者命名：**P**eter Spirtes 和 **C**lark Glymour）：
1. 从一个完全连接的图开始
2. 测试所有变量对之间的条件独立性
3. 在变量独立的地方移除边（以其他变量的子集为条件）
4. 使用碰撞点检测（V-结构）定向剩余边
5. 传播定向约束以解决模糊边

## 方法论

本书发展了：

1. **形式基础**：因果图被定义为变量上概率分布的表征。引入了**因果马尔可夫条件**和**忠诚度假设**作为将图与分布联系起来的公理。

2. **PC 算法**：一个在假设没有未观察到的混淆因素（或通过 FCI 算法显式处理潜变量）下进行因果发现的多项式时间算法。

3. **统计检验**：算法需要条件独立性检验。本书讨论了：
   - 参数检验（高斯：偏相关）
   - 非参数检验（基于核、互信息）
   - 离散检验（G²、χ²）

4. **扩展**：用于潜变量的 FCI（快速因果推断），用于非线性关系的 CDNI，以及用于稳健性的保守变体。

## 核心发现

### 1. 因果结构在假设下可以从观测数据中识别

在因果马尔可夫条件和忠诚度假设下，真实因果图可以从观测数据中**识别到马尔可夫等价**。这意味着：
- 如果数据和两个图都一致，你就无法区分 X → Y 和 Y → X
- 但你可以使用碰撞点检测来区分 X → Y → Z 和 X ← Y → Z

### 2. 忠诚度假设很强但可检验

忠实性：如果真实因果图暗示独立性，那么独立性在数据中成立（没有「偶然」抵消）。

这在以下情况下被违反：
- **路径抵消**：X 和 Y 之间的两条路径有相反的效应，相互抵消
- **确定性关系**：Y 是 X 的确定性函数，掩盖了其他依赖关系

本书讨论了削弱忠诚度假设的保守变体。

### 3. 潜变量使因果发现复杂化但不阻止它

FCI 算法将 PC 扩展到处理未观察到的混淆因素。它产生一个**部分祖先图（PAG）**而不是 DAG，表示具有潜变量的因果结构的等价类。

### 4. 样本复杂性是一个实际障碍

条件独立性检验的数量随变量数量组合增长。对于 n 个变量，最坏情况复杂性是 O(n² · 2ⁿ)。在实践中，在适当的稀疏性假设下，算法对于 n < 100 是可行的。

## 方法论评析

| 优点 | 局限 |
|---|---|
| 提供了因果发现的原则性、自动化方法 | 忠诚度假设很强，在现实数据中经常被违反 |
| PC 算法是多项式时间的（在稀疏性下） | 样本复杂性很高；小数据集产生不可靠的图 |
| 通过 FCI 处理潜变量 | FCI 比 PC 慢得多，可靠性也差得多 |
| 在合成和真实数据集上经过充分测试 | 现实世界变量通常定义不清（「智力」是什么？） |

## 与 `causal-memory` 的连接

### 1. `meta_causal_edges` 作为自动化因果发现

我们的 v0.3 路线图包括激活 `meta_causal_edges` 表进行**跨任务模式挖掘**。PC 算法为这提供了理论框架：

**输入**：来自多个任务的因果边集
```
[concurrency] mutex → deadlock
[caching] no_ttl → memory_leak → OOM
[database] missing_index → slow_query → timeout
```

**应用 PC 算法**：
1. 提取变量：{mutex, deadlock, no_ttl, memory_leak, OOM, missing_index, slow_query, timeout}
2. 测试条件独立性：给定「memory_leak」，「deadlock」是否与「OOM」独立？
3. 构建图：共享原因、共同效应、中介变量

**输出**：更高层次的因果结构
```
resource_misconfiguration → system_failure
  ├── [concurrency] mutex → deadlock
  ├── [caching] no_ttl → memory_leak → OOM
  └── [database] missing_index → slow_query → timeout
```

这**不是**在原始数据上运行 PC 算法——而是在**因果图本身**上运行它，将边视为数据点。

### 2. 从经验因果图到形式化因果模型

`causal-memory` v0.2 存储**经验因果链接**（观察到的决策→结果对）。PC 算法建议了一条通往**形式化因果模型**的路径：

1. **积累**足够的因果边以检测统计模式
2. **在边集上运行 PC** 以发现更高阶的结构
3. **为每个 `task_tag` 生成一个经过验证的因果图**
4. **使用 Pearl 的 do-演算查询图进行干预推理**

这在「智能体经验」（经验的）和「因果推断」（形式的）之间架起了桥梁。

### 3. 处理智能体因果图中的混淆因素

智能体因果图中的一个关键挑战是**上下文的混淆**：
- 智能体在上下文 C 中做出决策 D
- 结果 O 发生
- D 是 O 的原因，还是 C 是原因？

PC 算法的碰撞点检测有助于这里：
- 如果 D 和 O 都与 C 相关
- 但给定 C，D 和 O 是独立的
- 那么 C 是混淆因素，不是 D

这可以用于**纠正置信度水平**：通过混淆因素调整检验存活的边获得更高的置信度。

### 4. 实际限制 → 启发式近似

PC 算法的样本复杂性对于小因果图（智能体可能只有 50–100 条边）是令人望而却步的。与其运行完整的 PC，我们可以使用**启发式变体**：

- **频繁模式挖掘**：找到在多个任务中出现的决策→结果对
- **矛盾检测**：如果 D→O 在任务 A 中但 D→¬O 在任务 B 中，标记以供审查
- **相似性聚类**：通过决策/结果文本相似性对边进行聚类

这些是 PC 核心功能的近似，适应于智能体的稀疏数据场景。

## 阅读顺序

在 Pearl (2009) 之后阅读。Pearl 告诉你因果模型*是什么*；Spirtes 告诉你*如何从数据中发现一个*。两者共同定义了 v0.5 路线图：从智能体经验中学习因果结构，然后使用 do-演算查询它。
