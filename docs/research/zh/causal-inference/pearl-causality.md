# Pearl (2009) — 因果性：模型、推理与推断

## 完整引用

Pearl, J. (2009). *Causality: Models, Reasoning, and Inference* (2nd ed.). Cambridge University Press. ISBN: 978-0521895606

## 摘要

这是现代因果推断的基础文本。Pearl 引入了**结构因果模型（SCM）**框架，它统一了：
- **图模型**：DAG 表示因果结构
- **概率论**：条件概率编码观测数据
- **干预演算**：do-算子（do(X=x)）表示干预
- **反事实逻辑**：关于假设世界的虚拟推理

本书定义了**因果梯级**——三个因果推理层级，每个层级严格强于前一个：

1. **关联（第 1 级）**：P(Y|X) —— 看 / 观察
2. **干预（第 2 级）**：P(Y|do(X)) —— 做 / 行动
3. **反事实（第 3 级）**：P(Y_x|X=x', Y=y) —— 想象 / 回顾

## 方法论

本书将因果推断发展为**数学形式化**：

1. **公理化基础**：SCM 使用结构方程（Y = f(X, U)）定义，其中 U 表示未观察到的噪声。

2. **图标准**：**后门标准**、**前门标准**和 **d-分离** 提供了可识别性的图条件——什么时候可以从观测数据中估计 P(Y|do(X))？

3. **Do-演算**：操作因果表达式的三条推理规则：
   - 规则 1：忽略观测（P(y|do(x), z) = P(y|do(x)) 如果 Y ⊥ Z | X 在 G_X 中）
   - 规则 2：行动/观测交换（P(y|do(x), do(z)) = P(y|do(x), z) 如果 Y ⊥ Z | X 在 G_XZ 中）
   - 规则 3：忽略行动（P(y|do(x), do(z)) = P(y|do(x)) 如果 Y ⊥ Z | X 在 G_XZ(W) 中）

4. **反事实推断**：反事实通过修改结构方程并通过图传播变化来推导。

## 核心发现

### 1. 因果梯级是严格的层次结构

| 梯级 | 能力 | 示例 |
|---|---|---|
| 1（关联） | 从观测中预测 | 「吸烟者的肺癌发病率更高」 |
| 2（干预） | 从行动中预测 | 「如果我强迫某人吸烟，他们会得癌症吗？」 |
| 3（反事实） | 回顾性推理 | 「如果这个病人从未吸烟，他们会得癌症吗？」 |

每个梯级都需要比前一个严格更多的信息。你不能仅用关联数据回答干预问题。

### 2. 因果 DAG 不只是「带箭头的贝叶斯网络」

因果 DAG 编码**干预下的独立性假设**，不仅仅是观测下的独立性。边 X → Y 意味着「操纵 X 改变 Y 的分布」——不仅仅是「X 和 Y 相关」。

### 3. Do-算子使因果演算成为可能

Do-算子（do(X=x)）移除因果图中所有指向 X 的入边，模拟一个打破 X 自然原因的干预。这允许对「如果我做了 X 呢？」进行形式化推理，而无需运行实验。

### 4. 反事实可以从结构方程计算

给定：
- Y = f(X, U)
- 观测：X=x, Y=y

评估「如果 X 是 x'，Y 会是什么」：
1. 从观测数据中推断 U
2. 设置 X = x'（干预）
3. 计算 Y' = f(x', U)

这是**溯因-行动-预测**算法。

## 方法论评析

| 优点 | 局限 |
|---|---|
| 为因果性提供了完整、严格的数学框架 | 需要知道因果图（或能够发现它） |
| Do-演算对于可识别的因果效应是完备的证明 | 许多现实世界的因果查询无法从观测数据中识别 |
| 统一了图形的、概率的和反事实的推理 | 该框架假设没有未观察到的混淆（或显式建模它） |
| 反事实算法优雅且直观 | 结构方程在实践中通常是未知的；必须被估计 |

## 与 `causal-memory` 的连接

### 1. 我们在梯级上的当前位置

`causal-memory` v0.2 是一个**有抱负的第 1 级系统**：

| 梯级 | `causal-memory` 工具 | 状态 |
|---|---|---|
| 1（关联） | `search_causal`, `trace_cause` | ✅ 已实现 |
| 2（干预） | `counterfactual_query`（计划中） | 🔄 v0.5 |
| 3（反事实） | 完整反事实推理 | 🔄 v0.5+ |

这不是一个限制——它是一个**有原则的范围边界**。我们不声称实现了 Pearl 的完整框架。我们实现了对今天的 LLM 智能体有用的子集，并有一个清晰的路线图来攀登梯级。

### 2. 因果图作为「部分 SCM」

我们的 `causal_edges` 表是一个简化的结构因果模型：

```
SCM:  outcome = f(decision, noise)
causal-memory:  outcome_text = f(decision_text, confidence, discovered_by)
```

区别：
- **没有结构方程**：我们不建模函数形式 f(·)
- **没有未观察到的混淆因素**：U 隐含在 `confidence` 字段中
- **没有 do-演算**：我们不能形式化地计算 P(结果|do(决策))

相反，我们使用**经验频率**：如果「互斥锁」 → 「死锁」已被高置信度观察 10 次，我们就将其视为可靠的因果链接。

### 3. `relation` 字段作为简化的因果语义

我们的 `relation` 类型映射到 Pearl 的因果概念：

| `relation` | Pearl 等价物 | 含义 |
|---|---|---|
| `caused` | 直接因果边 | X → Y（干预 X 改变 Y） |
| `enabled` | 必要条件 | X 对 Y 是必要但不充分的 |
| `prevented` | 抑制边 | X → ¬Y（干预 X 减少 Y） |
| `no_effect` | 边的缺失 | X ↛ Y（干预 X 不改变 Y） |

这些是**结构约束**——它们编码在干预下会发生什么，而不仅仅是观察到了什么。

### 4. 路线图：干预查询（第 2 级）

v0.5 干预查询将如下所示：

```json
{
  "tool": "intervention_query",
  "params": {
    "action": "use channel communication",
    "context": "cache stampede protection",
    "predicted_outcome": "deadlock"
  }
}
```

系统将：
1. 检查「channel communication」 → 「deadlock」是否存在于因果图中
2. 如果没有，检查间接路径（channel → [中间] → deadlock）
3. 返回：「未发现直接因果链接。没有置信度 > 0.5 的间接路径。预测干预是安全的。」

这**不是**完整的 do-演算——它是基于经验因果图的启发式干预推理。

### 5. 路线图：反事实查询（第 3 级）

反事实查询：

```json
{
  "tool": "counterfactual_query",
  "params": {
    "actual": "used mutex lock",
    "hypothetical": "used channel communication",
    "observed_outcome": "deadlock"
  }
}
```

系统将：
1. 确认：「mutex lock」 → 「deadlock」存在（溯因）
2. 移除「mutex lock」 → 「deadlock」边（行动：设置 mutex = channel）
3. 检查「channel communication」 → 「deadlock」是否存在（预测）
4. 返回：「在反事实下，基于因果图中 0 条匹配边，死锁概率估计为 5%。」

这是应用于因果图的**溯因-行动-预测**算法。

## 阅读顺序

**如果你想知道完整的形式化目标是什么，读这篇。** Pearl 定义了一个完整的因果推断系统是什么样子。`causal-memory` v0.2 是一个小子集，但路线图很明确：从关联爬到干预再到反事实。
