# Wang 等 (2024) — 基于大语言模型的自主智能体综述

## 完整引用

Wang, L., Ma, C., Feng, X., Zhang, Z., Yang, H., Zhang, J., Chen, Z., Tang, J., Chen, X., Lin, Y., Zhao, W. X., Wei, Z., & Wen, J.-R. (2024). A Survey on Large Language Model based Autonomous Agents. *Frontiers of Computer Science*, 18(6), 186345. https://doi.org/10.1007/s11704-024-40231-1

## 摘要

本文全面概述了基于 LLM 的自主智能体，涵盖其架构（规划、记忆、工具使用）、应用（编码、科学、日常生活）和评估基准。本文将记忆识别为智能体架构的三个核心组件之一（与规划和工具使用并列），并综述了现有的记忆实现。

与记忆相关的关键发现：
- 大多数智能体记忆系统使用**检索增强生成（RAG）**范式
- 记忆通常分为短期（上下文窗口）和长期（向量数据库）
- **没有现有系统将因果关系作为主要数据结构存储**
- 记忆评估不发达——大多数基准测试测试回忆，而不是因果推理

## 方法论

这是一篇**综述论文**，不是实证研究。方法论是：

1. **系统文献综述**：作者在 2022–2023 年搜索了 arXiv、ACL Anthology、NeurIPS、ICML 和 ICLR 上关于 LLM 智能体的论文。

2. **分类构建**：论文按以下方式分类：
   - 智能体架构（单智能体 vs. 多智能体）
   - 记忆机制（短期、长期、混合）
   - 应用领域（编码、科学、网络、具身）

3. **基准比较**：现有评估基准在任务多样性、记忆需求和因果推理需求等维度上进行比较。

## 核心发现

### 1. 记忆是核心组件但理论不足

> 「虽然记忆模块在智能体架构中无处不在，但它们的设计往往是临时的，缺乏统一的理论框架。」（p. 8）

大多数记忆系统是工程解决方案（向量数据库 + 提示注入），没有扎根于认知科学或形式记忆理论。

### 2. RAG 占主导，但 RAG 不够

本文识别了三种记忆范式：
- **基于 RAG**：检索相关文本块，注入上下文（LangChain、LlamaIndex）
- **参数化**：微调 LLM 以「记住」（昂贵，不灵活）
- **混合**：将 RAG 与结构化存储结合（生成式智能体、MemGPT）

这些范式都不支持**因果遍历**（「什么导致了 X？」 → 「什么导致了那个原因？」）。

### 3. 评估基准不测试因果记忆

现有基准测试：
- **回忆**：「智能体在 10 轮之前还记得事实 X 吗？」
- **一致性**：「智能体的答案与其之前的陈述匹配吗？」
- **规划**：「智能体能将任务分解为步骤吗？」

没有测试：
- **因果归因**：「智能体为什么做出决策 Y？」
- **反事实推理**：「如果智能体选择了 Z 会发生什么？」
- **经验转移**：「智能体能将任务 A 的教训应用到任务 B 吗？」

### 4. 多智能体记忆共享未被探索

本文注意到，多智能体系统（AutoGen、MetaGPT）各自维护独立的记忆存储。没有机制用于：
- 跨智能体共享因果教训
- 解决智能体之间的因果信念冲突
- 构建集体因果模型

## 方法论评析

| 优点 | 局限 |
|---|---|
| 全面覆盖 2022–2023 年智能体文献 | 领域快速演变意味着一些近期工作（2024）被省略 |
| 清晰的分类有助于导航领域 | 分类有些任意；一些系统跨越类别 |
| 识别记忆评估是一个关键空白 | 没有为已识别的空白提出解决方案 |
| 结构良好且易于理解 | 一些部分是描述性的，而不是分析性的 |

## 与 `causal-memory` 的连接

### 1. 市场空白确认

本文是因果记忆是**真实空白**的**主要证据**，而不是现有系统「只是还没做到」的功能。作者明确声明，没有综述的系统将因果关系作为主要数据结构存储。

这证明了 `causal-memory` 作为**互补层**的存在，而不是竞争对手。

### 2. RAG vs. 因果图：架构区别

| 基于 RAG 的记忆 | 因果图记忆 |
|---|---|
| 存储：文本块 | 存储：决策→结果边 |
| 检索：语义相似度 | 检索：图遍历 |
| 查询：「找到像 X 的文本」 | 查询：「找到 X 的原因」 |
| 结构：扁平（向量空间） | 结构：有向图 |
| 压缩：向量嵌入 | 压缩：边抽象 |

`causal-memory` 不是「带额外元数据的 RAG」。它是**用于不同查询类型的不同数据结构**。

### 3. 评估空白 → 我们的基准路线图

本文发现没有基准直接测试因果记忆，这塑造了我们的 v0.4 路线图：
- **LongMemEval 集成**：测试因果回忆 vs. 事实回忆
- **因果推理基准**：设计需要因果遍历的探针问题
- **跨任务转移基准**：衡量任务 A 的教训是否提高了任务 B 的性能

### 4. 多智能体记忆共享（v0.5+）

本文观察到多智能体系统有孤立的记忆存储，映射到我们的 v0.5 路线图：
- **因果图导出/导入**：智能体可以共享因果子图
- **集体因果模型**：多个智能体贡献于共享因果图
- **冲突解决**：当智能体在因果性上不一致时，系统标记矛盾以供人类审查

## 阅读顺序

读这篇来理解**因果记忆在智能体记忆版图中的位置**。它确认我们不是重新发明 Mem0——我们填补了一个 Mem0（设计如此）不处理的空洞。
