## Method (round 1, frozen at `v0.9.0-amc1`)

### What is stored

The `Add` endpoint stores every received memory chunk verbatim in SQLite under its `user_id` (the retrieval isolation boundary) with `session_id` grouping and the original timestamp. Storage is synchronous: `Add` returns `200` only after the messages are committed and searchable.

### How retrieval works (round 1)

`Search` fuses **two signals** per memory and ranks by the combined score:

1. **Lexical (shared-prefix matching)**: tokenize query and memory with the
   project's tokenizer (ASCII word tokens, stop-word filtered; CJK character
   bigrams). A query token matches a memory token when they share a
   **common prefix of ≥ 4 characters** (`editor` ↔ `editing`,
   `deployment` ↔ `deploy`) — one rule that absorbs English morphology
   without a stemmer table. Lexical score = Σ over query tokens of
   `1 + ln(hits)`.
2. **Semantic (offline fastembed)**: when the server is built with
   `--features local-embed`, every stored chunk is embedded at Add time with
   the in-process ONNX model (BAAI/bge-small-en-v1.5, 384 dims, ~130 MB,
   downloaded once, no API key, no runtime network). At Search time the
   query is embedded (with the BGE retrieval instruction prefix) and cosine
   similarity is added to each candidate, weighted `sim × #query-tokens` so
   a semantic hit counts like one lexical hit. No embedder available →
   lexical-only, with no other behavior change.

Results are returned ordered most-relevant first, capped at `top_k`. No
answer generation happens in `Search` — the platform's answer model receives
the returned memory evidence. No state is shared across samples; `user_id`
isolation is enforced in every query.

> macOS note: linking the local ONNX backend on macOS requires a full Xcode
> SDK (the Command-Line Tools CoreML framework lacks classes the bundled
> ONNX Runtime references). The Docker image (Linux) builds and runs the
> fused server out of the box.

### Design notes (round 1)

- The memory text is the raw chunk (the platform controls which chunks constitute a sample's write stream), so the system is dataset-agnostic.
- The per-user corpus is the scoring scope — evaluation-scale corpora stay tractable without external indexes.
- The AMC server carried a private retrieval implementation (its own lexical scoring + fusion); the full causal-memory system was not in its path.

## Run instructions (current `main`; round-1 instructions live at the frozen tag)

### Docker (platform route)

The image builds with `--features local-embed` (semantic fusion included) and
runs `--write-mode raw` by default (no LLM keys on the platform):

```bash
docker build -t causal-memory-amc .
docker run -p 8787:8787 -v amc-data:/data causal-memory-amc
# API entrypoint: http://<host>:8787  (POST /add, POST /search, GET /health)
# Per-user DBs: /data/stores (override with AMC_DB_DIR)
# Write mode:   raw (default) | distill via -e AMC_WRITE_MODE=distill
#               (distill also needs CAUSAL_MEMORY_LLM_* env)
# Cold start downloads the fastembed model once (~130 MB, ~1 min);
# pre-warm by mounting a cache at /data/fastembed-cache.
```

### Direct (self-hosted route)

```bash
# Semantic fusion (offline fastembed; needs a full Xcode SDK on macOS):
cargo build --release --bin causal-memory-amc --features local-embed
# BM25-only (no embedder):
cargo build --release --bin causal-memory-amc
./target/release/causal-memory-amc --db-dir amc_data --port 8787 --write-mode raw
```

### API contract compliance

- `POST /add` — `{request_id, messages[{role, content, timestamp?}], user_id, session_id}` → `200 {success, request_id, user_id, session_id}` after durable storage.
- `POST /search` — `{query, user_id, top_k, options?}` → `{data: [{id, content, score, created_at?}]}` ordered by relevance; empty `data` when nothing matches.
- `GET /health` — `{status: "ok"}`.
- No authentication on the endpoints themselves; the platform's key flow applies at the deployment layer.
- Internal model usage (default `raw` mode): none (BM25 inverted index + local
  ONNX embeddings; no LLM API calls) — trivially satisfies the gpt-4o-mini
  model constraint. `distill` mode is self-hosted-only (external LLM env).

### Self-test

```bash
cargo test -p causal-memory-cli --bin causal-memory-amc   # Add→Search round-trip, user isolation, top_k, empty-search, distill-degrade
```

## Post-freeze improvements (on `main`, next round)

Round-1 result: **#1 in the coding scenario**, with weaker text recall — the
platform's answer model only sees what `Search` returns, so recall@top-k is the
binding constraint. Changes landed on `main` (tag `v0.9.0-amc1` stays frozen):

1. **IDF-weighted lexical scoring** — common tokens ("code", "build") no
   longer add equal background to every memory; rare discriminative tokens
   carry the ranking. `idf = ln((N+1)/(df+1))` over prefix-aware document
   frequency.
2. **Adaptive prefix threshold** — short tokens (git, vim, api, ide) now
   lexical-match at their own length. The old flat ≥4-char rule could never
   match a 3-char token, leaving it to the small embedder alone.
3. **Reciprocal rank fusion (RRF)** — the module contract always promised
   RRF; the code summed raw scores (lexical unbounded vs cosine in [-1,1],
   so keyword-heavy noise chunks dominated). Now each signal contributes
   `1/(60 + rank)` — rank-based, scale-invariant.
4. **Single-track: the AMC server now runs the production memory system.**
   The private AmcStore/scoring/RRF (~400 lines) is deleted; `/add` and
   `/search` map to the shared `Memory` facade (`remember` /
   `search_memory_entries`) — the same pipeline as the MCP server and the
   Python bindings. Retrieval is the production stack: persistent BM25
   inverted index, entity-boosted semantic retrieval, 1-hop expansion,
   RRF fusion. `user_id` isolation became physical (one SQLite store per
   user). `--write-mode distill|raw` selects the write strategy: full
   write-time LLM distillation (self-hosted, needs env) vs raw turns into
   the retrieval pool (platform default — the round-1 behavior). Both modes
   share the same retrieval stack, so an A/B rerun isolates the value of
   write-time distillation.

Verified by `cargo test --workspace` (346 tests green, clippy clean), incl.
the AMC self-suite (Add→Search round-trip, per-user isolation, top_k,
empty-search, distill-without-LLM degradation).
